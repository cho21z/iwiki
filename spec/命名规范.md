# 命名规范

## 一、目录命名

| 规则 | 说明 |
|------|------|
| 全部小写英文 | 不用驼峰，不用大写开头 |
| 统一单数 | 表达领域或分类，不表达数量 |
| 多词使用连字符 | 如 `cloud-native`、`system-design` |
| 只用公认缩写 | `os`、`mq`、`k8s`、`rpc`、`cicd` 等可以使用，其余尽量写全称 |

统一使用全小写英文目录，便于在 CLI 中快速切换，避免频繁切换输入法。

## 二、文件命名

文件名应当**准确、简洁、可检索**地概括卡片内容。问句和陈述式标题均可，具体形式由内容范围决定。

### 核心规则

1. **检索优先**：包含读者学习、复习或日常开发中最可能搜索的核心术语。
2. **范围明确**：看到文件名即可大致判断卡片讨论什么，避免 `数据库补充.md` 等模糊名称。
3. **形式自由**：单一问题可使用问句；综合主题、机制、对比和选型内容可使用陈述式标题。
4. **关键词适量**：综合卡片通常保留一至三个核心检索词，不为覆盖所有章节无限加长文件名。
5. **术语统一**：中文为主，技术术语保留官方或行业通用写法，如 `Redis`、`NoSQL`、`Reactor`。
6. **不加无意义序号**：除非序号本身表达不可替代的学习顺序。
7. **统一 Markdown**：文件扩展名使用 `.md`。

### 推荐形式

| 内容类型 | 推荐形式 | 示例 |
|----------|----------|------|
| 单一问题 | 问句 | `架构设计为什么需要权衡.md` |
| 综合主题 | `主题范围-核心检索词` | `数据库高性能架构-读写分离与分库分表.md` |
| 技术对比 | `对象-对比主题` 或 `对象对比` | `IO多路复用-select-poll-epoll-kqueue对比.md` |
| 运行机制 | `技术名称-机制` | `MySQL主从复制机制.md` |
| 算法与选型 | `主题-算法与选型` | `高性能集群-负载均衡层级与算法.md` |

> 文件名首先负责知识定位，不必为了统一形式全部写成问句；具体问题可以放在卡片内部展开。

## 三、索引规则

文件名只承载最核心的检索词，目录 `README.md` 用于补充二级索引：

- 按学习顺序列出卡片；
- 列出每张卡片的主题范围；
- 建立子知识关键词到卡片的映射；
- 卡片重命名后同步更新索引和内部链接。

## 四、不允许出现的特殊字符

为避免跨平台兼容问题，文件名不使用以下字符：

`?` `*` `:` `<` `>` `|` `"` `/` `\`
