# 知识卡片整理原则

## 一、定位

知识卡片用于沉淀相对独立的知识主题，帮助读者建立理解、形成知识联系，并在遗忘后快速恢复认知。工程决策与面试复习是学习成果的应用，而不是卡片组织的首要目标。

卡片来源可以是个人笔记、学习复述或会议纪要。整理时应忠实保留作者关注的知识点，同时理顺逻辑、纠正错误并补充必要内容。卡片不是官方手册的替代品，不以覆盖全部参数和操作细节为目标。

## 二、整理流程

1. **提取主线**：识别材料真正回答的核心问题和知识层次，删除过程性纪要与重复表达。
2. **纠错整理**：直接修正事实错误和逻辑问题，不在正文中保留错误版本。
3. **组织内容**：根据知识本身选择合适的章节和表达方式，不套固定模板。
4. **补充内容**：补充日常常见、工程常用或有助于建立完整理解的知识；明显偏离主线或存在争议的内容先征求作者意见。
5. **决定拆分**：按认知闭环判断是独立成卡还是留作主卡章节。
6. **复核定稿**：检查标题、术语、图表、内部链接和知识边界。

## 三、拆分原则

1. **一条知识主线一卡**：定义、原理、分类、方案和权衡若服务于同一核心主题，应放在同一卡片的不同章节。
2. **优先参考学习层次**：先沿用原始材料的主题结构；若存在重复、交叉或跨度过大，再按逻辑关系调整。
3. **不按零散问题机械拆卡**：常见追问优先作为主卡内部章节；只有具备独立理解或选型价值时才单独成卡。
4. **形成认知闭环再拆**：子主题应能独立说明背景、核心机制和关键边界，不能只截取零散结论。
5. **兼顾浏览效率**：如果单卡过长，已无法通过一次快速浏览恢复整体认知，可将最独立的子主题拆出，并建立相互链接。

## 四、内容质量要求

1. **结论优先**：开头应尽快回答标题所表达的主题或问题，使读者能快速恢复核心认知。
2. **保留关注点**：作者原本记录的重要内容和底层原理应保留；允许重组和纠错，但不因追求简短而随意删除。
3. **结构服从内容**：章节、顺序和篇幅由知识本身决定，不为形式完整添加无意义内容。
4. **强调权衡**：介绍收益时同时说明代价、边界、风险和替代方案，避免只写优点。
5. **避免手册化**：仅保留理解和决策所需的最小用法；完整参数、返回值、错误码和操作步骤在使用时查阅权威文档。
6. **谨慎使用阈值**：数据量、吞吐量、时延等数字如非普遍标准，应标注为经验值或示例，不写成固定结论。
7. **保留有效版本信息**：仅记录会影响理解、兼容性或技术选型的版本门槛。
8. **术语准确统一**：使用行业通用术语；同一概念在仓库内保持一致写法。
9. **语言正式清晰**：正文采用书面语，可对外发布；中文表达为主，保留知识点自身的英文术语。

## 五、可选内容模块

以下模块按需选用，不要求全部出现，也不规定固定顺序：

| 内容模块   | 适用情况                         |
| ---------- | -------------------------------- |
| 核心结论   | 需要快速回答标题或概括主题       |
| 定义与边界 | 概念范围容易混淆                 |
| 背景与目的 | 需要说明技术为何产生             |
| 核心原理   | 需要理解内部机制                 |
| 工作流程   | 存在明确的运行步骤或交互顺序     |
| 分类与模型 | 包含多种实现形式                 |
| 适用场景   | 涉及技术选型                     |
| 最小用法   | 存在命令、API 或配置             |
| 对比与辨析 | 存在相似概念或替代方案           |
| 权衡与限制 | 方案存在明显代价和边界           |
| 常见问题   | 有值得集中解释、复习或辨析的追问 |
| 延伸知识   | 内容重要但不属于主线             |

## 六、图表原则

图表用于降低理解成本，不作为每张卡片的硬性要求：

- 角色和依赖关系复杂时使用架构图；
- 运行过程复杂时使用流程图或时序图；
- 多个方案需要比较时使用表格；
- 一段文字已经能清楚说明时，不强行添加图表；
- 图表必须承载有效信息，不作为装饰。
